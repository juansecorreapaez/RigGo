# 12.3.7 — execution run compatibility

Build `2026-09-26-1237-A1`.

## Database

`db/12.3.7_stale_run_compat_hotfix_APPLIED.sql` changes `riggo_execution_run_guard_1236()` so a v2 or v3 save carrying the current `_riggoRunId` can continue through existing permissions and revision checks. A missing or different ID remains blocked with `stale_execution_run`. Atomic Reset and Activation retain their exceptions; Activation generates the new ID on the server. The script checks expected functions and trigger before replacing the guard. It contains no update to current Move or execution rows.

The earlier `db/12.3.6_reset_baseline_APPLIED_DO_NOT_RERUN.sql` added the Reset RPC and run guard. Its original guard also depended on a session setting made by v3 but not v2; 12.3.7 removes that extra dependency.

## Browser

C4 recognizes stale-run responses, checks queued work against the current server run, discards work from an older run, and adopts server state without merging execution across runs. The release retains the 12.3.6 operational, field integrity, Move Intelligence, CSS, and template files.

## Verification boundary

The 31 `site/` files have a recorded checksum manifest and can be verified locally. Earlier browser checks used a simulated backend; the scripts depended on fixtures outside this repository and have been removed. This repository does not contain a reproducible end-to-end suite or proof that the 12.3.7 frontend is deployed. A reported production save succeeded after the database guard change; that observation does not establish the live frontend version or a two-device Reset/Reactivate result.
