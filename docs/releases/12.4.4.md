# RigGO 12.4.4

The operating Close Move button used a private legacy function that marked a Move closed locally. The existing global atomic-close patch did not replace that lexical binding. The button now delegates to the existing atomic server authority and changes lifecycle only after acknowledgement.

During reconciliation, lifecycle fields come from the server while other pending edits remain local. Reading a newer revision no longer silently advances a pending operation's expected revision. Recognized legacy completion rejections can retry only after an IndexedDB backup is committed. Backup failure preserves the original operation and local state. Unrelated rejections, delete intentions and active Moves are not automatically cleared or completed.

Recognized retries use the queued comparison baseline: disjoint server edits are retained and overlapping field or array changes remain blocked for review. Missing baselines do not trigger automatic overwrites. Changes made locally during the backup are also retained.

The sync status opens a keyboard-accessible English/Spanish review of pending saves, with backup download and backed-up retry. The local repair database is separate from operational media and existing queues.

A canonical www link is provided. There is no automatic cross-origin redirect, because existing browser-local data must remain reachable at both origins during recovery.

Server maintenance separately backed up and reconciled five reviewed master lifecycles using their existing execution acceptance dates. Execution records, revisions, reports and media were preserved. Maintenance snapshots are private; no production snapshots or user records are included in this repository. The proposed global execution trigger was not applied; the scoped repair uses the existing server lifecycle rules.

Validation is recorded in docs/VALIDATION_RESULTS_12.4.4.json: 26 closure/reconciliation checks, 14 desktop/mobile English/Spanish checks, 7 checks across two isolated browser users and a real Service Worker upgrade test. The two-user test verifies backed-up recovery, current revision use, adoption of disjoint remote edits and a common completed status. The upgrade test verifies offline boot and retention of queued changes, account language preference and local evidence. Tests isolate production services and do not send real email. Browser tests used Playwright 1.62.1. This branch supplies the static update; Cloudflare deployment is a separate step.
